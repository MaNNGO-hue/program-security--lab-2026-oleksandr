# Стратегія симетричного криптографічного захисту SafeVault (ЛР №6)

## 1. Об'єкти шифрування та момент обробки даних
* **Чутливі дані, що підлягають шифруванню:**
  * вміст конфіденційних одноразових нотаток (`SecretNote.encryptedContent`);
  * резервні коди відновлення МФА користувачів.
* **Момент шифрування та розшифрування:**
  * шифрування виконується на рівні сервісу бізнес-логіки безпосередньо перед збереженням запису у сховище;
  * розшифрування виконується лише після успішної автентифікації та авторизації суб'єкта (`AccessControlPolicy`) та перевірки тегу цілісності.

## 2. Криптографічні примітиви та режим шифрування (AEAD)
* **Алгоритм і режим:** `AES-256-GCM` (Authenticated Encryption with Associated Data — автентифіковане шифрування), що одночасно забезпечує конфіденційність, цілісність та автентичність даних.
* **Довжина ключа:** 256 біт (32 байти).
* **Одноразове число (Nonce / IV):** 96 біт (12 байтів), генерується криптографічно стійким генератором `SecureRandom` унікально для кожної операції шифрування. Повторне використання пари `(Key, Nonce)` заборонено.
* **Автентифікаційна мітка (Auth Tag):** 128 біт (16 байтів); розшифрований текст відхиляється (`AEADBadTagException`) у разі модифікації хоча б одного біта шифротексту або Nonce.

## 3. Зберігання та ротація криптографічних ключів
* **Зберігання:** майстер-ключ шифрування передається через змінну середовища (`SAFEVAULT_MASTER_KEY`) або захищене сховище секретів; зберігання ключів у коді чи Git-репозиторії заборонено.
* **Ротація:** кожний зашифрований пакет зберігає префікс версії ключа (`v1:...`), що дозволяє впроваджувати нові версії ключів (раз на 90 днів або при компрометації) без втрати можливості розшифрувати раніше створені активні нотатки.
