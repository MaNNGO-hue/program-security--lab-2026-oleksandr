# Політика контролю цілісності та автентичності SafeVault (ЛР №7)

## 1. Аналіз компонентів, загроз та обраних криптографічних механізмів
| Компонент / Дані | Загроза порушення | Обраний механізм | Призначення |
| :--- | :--- | :--- | :--- |
| Файли конфігурації (`pom.xml`) та архівні дампи журналу аудиту (`AuditLog`) | Випадкове пошкодження або несанкціонована підміна параметрів | Криптографічне хешування **SHA-256** (зберігання еталонного хешу в захищеному середовищі) | Контроль незмінності системних артефактів і логів |
| Метадані та записи конфіденційних нотаток у БД (`noteId`, `ownerId`, `maxViews`, `expiresAt`, `requiresMfa`) | Внутрішня підміна (Tampering) прав доступу, лічильника переглядів або терміну дії в обхід бізнес-логіки | Код автентичності повідомлень **HMAC-SHA256** (256-бітний секретний ключ) | Одночасне підтвердження цілісності та автентичності походження запису |
| Зашифрований вміст нотатки (`SecretNote.encryptedContent`) та резервні коди МФА | Перехоплення та цілеспрямована модифікація шифротексту (`Bit-flipping`) | Автентифіковане шифрування **AES-256-GCM (AEAD)** із 128-бітним `Auth Tag` | Одночасне забезпечення конфіденційності, цілісності й автентичності |

## 2. Керування ключами та еталонними значеннями
* **Секретний ключ HMAC (`SAFEVAULT_HMAC_KEY`):** 256-бітний ключ генерується криптографічно стійким генератором `SecureRandom`, зчитується зі змінних середовища та ніколи не зберігається у відкритому коді чи базі даних[cite: 16].
* **Розділення ключів:** ключ для обчислення `HMAC-SHA256` відокремлений від майстер-ключа симетричного шифрування `AES-256-GCM`[cite: 16].

## 3. Момент перевірки та реакція системи на порушення
* **Формування контрольного значення:** `HMAC-SHA256` обчислюється сервісом `IntegrityProtectionService` у момент створення або легітимного оновлення запису нотатки від канонічного рядка критичних полів[cite: 16].
* **Момент перевірки:** безпосередньо перед читанням або зміною стану нотатки порівняння виконується функцією постійного часу (`MessageDigest.isEqual`) для захисту від атак за часом виконання (Timing Attacks)[cite: 16].
* **Реакція на порушення:** у разі невідповідності `HMAC` або тегу `AES-GCM` система негайно блокує операцію (`SecurityException` / HTTP `400 Bad Request` — *«Порушення цілісності даних! Запис було несанкціоновано змінено»*) і реєструє інцидент безпеки.
