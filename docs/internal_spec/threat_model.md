# Модель загроз системи SafeVault (методологія STRIDE)

## 1. Межі аналізу (Scope) та модель порушника
* **Межі аналізу:** публічний REST API (`POST /api/v1/notes`, `GET /api/v1/notes/{accessToken}`, `DELETE /api/v1/notes/{revokeToken}`), бізнес-логіка та криптографічний модуль (`service`, `crypto`), сховище даних PostgreSQL та фоновий планувальник очищення.
* **Модель порушника:**
  * *Зовнішній неавтентифікований порушник:* має доступ до мережевого інтерфейсу API, намагається підібрати токен доступу, перехопити трафік або викликати відмову в обслуговуванні (DoS).
  * *Компрометований отримувач / перехоплювач посилання:* отримав одноразове посилання та намагається прочитати нотатку повторно або експлуатувати стан гонитви (Race Condition).
  * *Внутрішній привілейований порушник (адміністратор БД / розробник):* має доступ до таблиць БД або логів сервера та намагається прочитати вміст чужих нотаток.

## 2. Аналіз загроз за методологією STRIDE
* **Spoofing (Підміна суб'єкта):** спроба підміни автора для дострокового видалення чужої нотатки або підбору `access_token` -> *Захист:* генерація 256-бітних токенів через CSPRNG, перевірка за криптографічним гешем SHA-256 та обмеження частоти запитів (Rate Limiting).
* **Tampering (Фальсифікація даних):** несанкціонована зміна зашифрованого тексту нотатки або лічильника `remaining_views` у БД чи під час передачі -> *Захист:* автентифіковане шифрування AES-256-GCM (контроль цілісності тегом автентифікації), TLS 1.2+ та параметризовані запити JPA/SQL.
* **Repudiation (Заперечення дій):** заперечення факту створення, прочитання або знищення конфіденційної нотатки -> *Захист:* незмінний журнал аудиту (`AuditEvent`) із фіксацією типу події та мітки часу UTC.
* **Information Disclosure (Витік інформації):** читання секрету адміністратором із БД, витік токена через логи сервера або повторне зчитування одноразової нотатки при паралельних запитах -> *Захист:* шифрування AES-256-GCM із ключем у змінній середовища `SAFEVAULT_MASTER_KEY`, заборона логування секретів, заголовок `Cache-Control: no-store` та песимістичне блокування запису (`PESSIMISTIC_WRITE`) у транзакції читання.
* **Denial of Service (Відмова в обслуговуванні):** масове створення нотаток великого обсягу або перебір токенів для вичерпання пам'яті й ресурсів БД -> *Захист:* обмеження розміру нотатки до 10 000 символів, Rate Limiting (20 запитів/хв з однієї IP-адреси), таймаути з'єднань та фонове очищення прострочених записів кожні 30 секунд.
* **Elevation of Privilege (Підвищення привілеїв):** використання токена читання (`access_token`) для виконання операції примусового відкликання або отримання адміністративного доступу до БД -> *Захист:* суворе розділення `accessTokenHash` і `revokeTokenHash` на рівні бізнес-логіки та принцип найменших привілеїв для облікового запису БД.
