# Політика безпеки програмного проєкту SafeVault

## 1. Мета та область дії (Purpose & Scope)
Політика встановлює обов'язкові вимоги безпеки для проєктування, розробки, тестування та супроводу вебсервісу **SafeVault** (REST API на базі Java 21 / Spring Boot 3.x, сховище PostgreSQL 16, репозиторій GitHub).

## 2. Базові принципи безпеки (Security Principles)
* **Принцип найменших привілеїв (Least Privilege):** обліковий запис БД застосунку має права лише на операції `SELECT`, `INSERT`, `UPDATE`, `DELETE` у робочій схемі без прав адміністратора БД.
* **Заборона відкритих секретів (No Plaintext Secrets):** майстер-ключ шифрування (`SAFEVAULT_MASTER_KEY`), паролі БД та приватні SSH-ключі ніколи не зберігаються в коді чи Git; використовуються лише змінні середовища.
* **Безпечні налаштування за замовчуванням:** усі з'єднання з API працюють виключно по HTTPS (TLS 1.2+), а налаштування CORS обмежують доступ лише довіреним доменам.

## 3. Безпечне середовище та реалізація (Secure Implementation)
* **Автентифікація та керування доступом:** токени доступу (`access_token`) та відкликання (`revoke_token`) генеруються через CSPRNG (256 біт) і зберігаються у БД лише у вигляді криптографічних гешів **SHA-256**.
* **Криптографічний захист:** вміст нотаток шифрується алгоритмом **AES-256-GCM** з унікальним 96-бітним вектором ініціалізації (IV) для кожного запису.
* **Валідація даних (Input Validation):** усі вхідні DTO перевіряються через Jakarta Validation (довжина тексту 1–10 000 символів, `ttl_minutes` від 5 до 10 080, `max_views` від 1 до 10).
* **Журналювання та помилки:** запис відкритого тексту секретів і токенів у логи суворо заборонений; відповіді про помилки не містять stack trace.

## 4. Перевірка безпеки та керування вразливостями
* Обов'язкове автоматизоване сканування залежностей Maven на відомі вразливості (CVE) перед релізом та покриття модулів `crypto` і `service` модульними тестами JUnit 5.
